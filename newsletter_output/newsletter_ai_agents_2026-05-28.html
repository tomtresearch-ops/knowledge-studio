The Agent Market Just Split in Two
Hermes dethroned the model wars, Cursor shipped its own $0.50 coding model, and healthcare agents are failing at 72%—revealing what actually matters.
May 28, 2026 · 3 min read
The agent market is maturing faster than anyone expected, and it's not going the way the hype predicted. The bottleneck isn't raw capability anymore—it's operational infrastructure. Three signals this week show where real money and adoption are actually flowing.
01
Infrastructure, Not Intelligence, Became the Moat
Hermes is now the production agent runtime of choice, processing 560B tokens daily versus 151B for its predecessor. It won by being reliable and observable—not by being smartest. Simultaneously, Cursor shipped Compos2.5, a proprietary coding model that matches frontier performance at 1/20th the cost ($0.50 per task instead of $11). The market moved from 'which model wins?' to 'which framework runs without breaking?'
Stop betting on model wars. If you're building agents, your competitive advantage lives in monitoring, recovery loops, and multi-agent coordination—not in which LLM you're calling. The companies winning are treating models as interchangeable and infrastructure as irreplaceable.
02
Humans Still Run the Show in High-Stakes Work
Healthcare agents are failing on 72% of U.S. medical workflows, and it's not because the models are dumb—Claude, GPT, and Gemini all fail on the same tasks. The problem: agents can't handle compliance handoffs, multi-step context retention, or graceful degradation when things go wrong. Meanwhile, coding agents paired with human approval loops are already generating revenue. The pattern is stark: agents as replacements fail; agents as amplifiers (drafts, documentation, approvals) ship.
If your domain requires human judgment, liability, or regulatory audit trails, don't design for full autonomy. Design for augmentation: approval loops, transparency, and documented handoffs. That's what's actually shipping in production today.
03
Context Is Now the Limiting Factor
Claude Code developers are building ad-hoc knowledge layers—GitHub integrations, codebase graph parsers, markdown skill libraries—to give the model explicit understanding of how code is organized. Teams are literally re-reading files 40 times because agents lack structural codebase understanding. Meanwhile, open-weight models in persistent environments (an 10-day MMO sim generated 93k training events) show that self-improving agents need stateful infrastructure most builders don't have. The gap isn't between models—it's between raw capability and domain-specific context.
Build lightweight knowledge layers (repo graphs, skill libraries, memory caches) on top of existing models instead of waiting for smarter ones. Infrastructure builders adding these abstraction layers to Claude Code and open-weight models will win the next category.
The Bigger Picture
The agent industry is bifurcating into two separate markets that aren't converging. Orchestrator-style agents (Claude Code + human loops) are production-ready and generating revenue today. Autonomous-style agents (Hermes, self-improving systems) are technically interesting but failing in regulated domains and hitting hard limits at scale. The real insight: model capability is 20% of the problem. The other 80%—memory management, error recovery, context retention, audit trails, operational reliability—is where the actual work and defensible value live. Every production team we're tracking is building infrastructure, not chasing benchmark improvements. The companies capturing value next are those optimizing the operational layer, not the model layer.
